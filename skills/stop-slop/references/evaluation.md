# 행동 검증

스킬을 만들거나 변경할 때 사용하는 자료다. 일반 윤문 작업마다 실행하지 않는다.

## 실행

1. `evals/cases.json`의 `request`와 `input`만 평가 모델에 전달한다. 실제 스킬과 필요한 언어 참고 자료를 읽게 하되 기대 결과와 실패 기준은 보여주지 않는다.
2. 사례마다 실제 출력과 실행 모델·날짜를 기록한다. 통과 사례만 골라 공개하지 않는다.
3. 아래 기준으로 원문과 결과를 대조한다. 가능하면 별도의 평가자에게 같은 원문·결과를 주어 검토하게 한다. 자동 문자열 검사와 의미 검토 결과를 구분한다.
4. 규칙 위반을 고친 뒤 영향을 받는 사례를 다시 실행한다. 실패를 피하려고 모든 글을 원문 그대로 반환하는지도 교정 사례로 확인한다.

## 필수 기준

- `checks`에 적힌 의미·문체·문서 역할이 모두 보존되는가?
- `forbidden_changes`가 하나라도 발생하면 그 사례는 실패다. 문체가 좋아졌다고 상쇄하지 않는다.
- `protected_literals`의 코드·경로·URL·인용은 정확히 유지되는가? 수치와 단위는 값과 관계를 함께 확인한다.
- `edit` 사례는 중복이나 군더더기를 실제로 개선해야 한다. `preserve` 사례는 무수정도 올바른 결과다.
- `review` 사례는 요청하지 않은 전체 교정문을 출력하지 않는다. `draft` 사례는 제공된 사실·관계·확실성을 지키면서 요청한 글을 만든다.
- 예시 표현과 글자 단위 일치, 길이 감소율, 금지어 개수로 의미 보존이나 품질을 판정하지 않는다.

## 품질과 반복 적용

필수 기준과 별도로 독자가 이해하기 쉬워졌는지, 원래 말투가 남았는지 평가한다. 원문과 교정문을 가리고 비교할 수 있지만 자체 평가 점수는 객관적인 보장으로 해석하지 않는다.

한 번 교정한 글을 다시 입력했을 때 새 사실·확신·약속이 추가되거나 필요 없는 수정이 누적되지 않는지도 확인한다. 이미 자연스러운 결과는 그대로 둘 수 있어야 한다.

## 범위

이 자료는 검증 입력과 기준이며 실행 결과가 아니다. 구조 검사, 예시 직접 검토, 실제 모델 행동 검증, 사람의 블라인드 비교는 서로 다른 확인이다. 수행한 것만 보고한다. 한 모델의 소수 사례 통과를 모든 언어·문서·모델에 대한 보장으로 확대하지 않는다.
