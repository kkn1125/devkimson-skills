# 업무 인수인계 DOCX 작성

인수자가 업무를 이어갈 수 있도록 기능과 처리 방법을 설명하는 문서를 작성합니다. 기본 독자는 외부 업무 담당자이며, 사용자가 지정한 수신자와 담당 범위를 우선합니다.

## 작성 전 확인

- 사용자가 맡은 업무와 수신자를 확인합니다. 대화에서 이미 정한 범위는 다시 질문하지 않습니다.
- 기존 작성본이 있으면 현재 파일을 읽습니다. 최초 생성본 이후 사용자가 수정한 내용은 새 문서에도 반영합니다. 버전이나 해시가 달라졌다면 사용자 수정본을 보존하고 별도의 개선본을 저장합니다.
- 전임자 문서를 제공받으면 본문, 표, 제목 구성을 읽고 문체와 설명 방식을 참고합니다. 과거 문서의 정책, SQL, 경로를 현재 사실로 옮기지 않습니다.
- 문체와 구성을 먼저 논의하자는 요청에는 짧은 예시를 보여주고 의견을 받은 뒤 작성합니다. 방향이 합의되면 작성과 검증을 끝까지 진행합니다.

## 문체

- 본문은 `~입니다.`, `~합니다.`, `~하였습니다.` 형태의 보고서 문체로 작성합니다. 제목, 표의 항목명과 짧은 값은 명사형으로 작성할 수 있습니다.
- 작성자가 수신자에게 전달하는 문서로 작성합니다. 작성자는 표지나 문서 상단에 기재하며, 본문에서 작성자를 제삼자로 평가하지 않습니다.
- `인수인계드립니다`, `맞춰주시면 됩니다`, `확인해 보시면 좋겠습니다` 같은 대화체를 사용하지 않습니다.
- 기능과 처리 순서를 직접 설명합니다. 근거가 없는 원인 추정이나 현재 상황에 대한 논평을 덧붙이지 않습니다. 장애 대응 설명이 필요한 경우 증상, 확인 위치, 처리 순서를 구체적으로 작성합니다.
- `현재 확인한 로컬 소스에는`, `사용자 확인에 따르면`, `최종 방식 확정으로 기록하지 않는다`처럼 조사 및 기록 과정을 설명하는 문장은 문서에서 제외합니다. 확인 범위의 한계는 사용자에게 따로 알립니다.
- 같은 주의사항을 본문, 표, 요약에서 반복하지 않습니다. 문장은 한 가지 처리나 기준을 설명하도록 짧게 작성합니다.

## 구성

문서 상단에는 제목, 작성자, 전달 대상, 작성일과 짧은 업무 범위를 기재합니다. 업무가 여러 개이면 업무별로 구분하여 다른 담당자의 문서와 취합하기 쉽게 작성합니다.

각 업무에는 다음 항목 중 실제로 필요한 내용을 배치합니다. 자료가 없는 항목을 빈 제목이나 형식적인 확인 문구로 채우지 않습니다.

1. **개요**: 기능의 목적과 담당 범위입니다.
2. **처리 절차**: 시작 조건, 실행 순서, 전달하는 값과 처리 결과입니다. 순서가 있는 작업은 번호 목록을 사용합니다.
3. **처리 기준 또는 설정**: 적용 대상과 집계 범위 등 업무를 이어받는 데 필요한 기준입니다.
4. **운영 확인 방법**: 확인할 화면, 데이터, 응답 결과와 확인 순서입니다.
5. **관련 API 및 소스 또는 자료 위치**: 확인된 API 경로, 파일명, 메서드명, 실행 방법이나 전달 자료입니다.

진행 일정과 미완료 업무는 필요할 때만 마지막 **진행 중인 사항**에 짧게 정리합니다. 완료한 작업, 예정 작업과 외부 회신 대기를 구분하고, 확정되지 않은 담당자나 일정을 만들지 않습니다.

티켓은 사실 확인 자료로 사용할 수 있지만, 기본 문서에는 티켓 번호, 제목, 링크, 코멘트 요약, 논의 경위와 처리 이력을 넣지 않습니다. 사용자가 요청한 경우에만 포함합니다. `관련 이력: 링크` 형식이나 문서 작성자의 준비 체크리스트도 기본 구성에서 제외합니다.

정책, 집계 기준과 연동 방향은 현재 근거로 확인합니다. 설명에 필요한 규칙은 티켓의 대화 형식 대신 기능의 처리 기준으로 작성합니다. 미확정 정책을 구현된 기능처럼 설명하지 않습니다.

## DOCX 제작 및 검증

- 사용 가능한 `docx` 또는 `documents` 스킬의 문서 제작 절차를 따릅니다. 이 스킬은 문체와 업무 구성 기준이며, Word 생성 도구를 새로 설치하거나 구현하는 이유가 되지 않습니다.
- 제공받은 문서의 형식과 사용자가 정한 형식을 우선합니다. 별도 형식이 없으면 단정한 제목, 일관된 본문 글꼴과 여백을 사용합니다. 기능 비교나 경로 목록처럼 필요한 곳에만 표를 사용합니다.
- 제목과 소제목에는 Word 제목 스타일을 사용합니다. 단계 목록은 실제 번호 목록을 사용하고, 절차별로 1부터 시작합니다.
- 표의 열 너비와 셀 너비를 맞추고 머리글을 반복합니다. 긴 API 경로, 파일명과 한글이 잘리거나 다른 셀을 침범하지 않도록 확인합니다.
- 인증키, 비밀번호와 개인 계정 정보는 본문에 넣지 않습니다. 필요한 경우 승인된 별도 공유 경로로 전달합니다.
- DOCX를 렌더링한 후 전체 페이지를 확인합니다. 줄바꿈, 표 분할, 제목이 본문과 떨어지는 현상, 빈 페이지와 페이지 번호를 점검합니다. 확인 도구의 한계를 실제 Word 확인으로 확대하지 않습니다.
- 렌더링 도구의 평가 표시가 있는 경우 최종 DOCX에 해당 표시가 들어 있지 않은지 확인합니다. 최종 파일은 정상 ZIP 및 XML 구조인지 확인합니다.
- 요청한 폴더에 저장하고 파일 존재와 복사 무결성을 확인합니다. 원본과 개선본의 구분은 사용자에게 알리며, 외부 발송은 별도 요청이 있을 때만 수행합니다.
- 작업 기록의 저장은 해당 워크스페이스 규칙을 따릅니다. 사용자가 요청한 DOCX 내보내기를 로컬 업무 기록의 복제 권한으로 해석하지 않습니다.

최종 응답에는 개선한 점과 최종 파일을 간단히 안내합니다. 자료 위치나 실제 운영 확인이 남아 있다면 사용자에게 따로 알립니다. 조사 과정 설명을 문서 끝에 추가하지 않습니다.
