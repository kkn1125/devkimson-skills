# Systematic Debugging

1. 기대 동작·실제 증상·환경·버전·입력·시각·영향 범위를 확보한다. 진단이 달라지는 누락 정보는 질문한다.
2. 가장 작은 실제 경로로 재현한다. 설정·전송·인증·응용 동작·영속성을 구분한다.
3. 호출자·오류 경로·로그·최근 변경을 읽고 관찰과 가설을 분리한다.
4. 경쟁 가설마다 반증할 수 있는 최소 검사를 정하고 한 번에 한 변수를 바꾼다.
5. 입증한 공유 원인을 최소 수정하고 기존 변경·오류 처리를 보존한다. 임의 캐시 삭제나 실패 은폐로 우회하지 않는다.
6. 깨졌던 행동의 회귀 검사, 영향받는 프로젝트 검사, 최종 diff를 확인한다.
7. 원인·수정·실제 근거·남은 가설·미실행 운영 확인을 보고한다.
