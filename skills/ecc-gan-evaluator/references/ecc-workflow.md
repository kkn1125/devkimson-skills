# Codex 작업 절차

먼저 [원본 자료](ecc-upstream.md)에서 이 작업의 목표·입력·도메인별 판단 기준·산출물을 읽는다. 해당 기술 항목을 다음 Codex 실행 절차에 적용한다. 호스트 전용 도구와 자동 실행 지시는 현재 기능으로 가정하지 않는다.

1. 원본에서 요청에 필요한 단계·입출력·의존성·완료 조건을 추출한다. 계획 요청과 구현 요청의 범위를 유지한다.

2. 현재 위임 승인이 없으면 같은 단계를 순차 수행한다. 허용된 경우 독립 작업만 나누고 증거·실패·한계를 통합한다.

3. ccg-workflow/codeagent-wrapper, tmux/dmux, 외부 모델·MCP·CLI는 실제 사용 가능 여부·인증·비용을 확인한다.

4. 없는 Workflow 도구나 외부 실행기를 가정하지 않고 현재 Codex 도구로 처리한다. 독립 검토가 없었으면 독립 검토를 했다고 하지 않는다.

5. 검토는 코드 맥락을 읽고 중복 지적을 합친 뒤 반박 검증을 거쳐 남은 구체적 문제만 보고한다. 불완전한 검토는 완료로 표시하지 않는다.

6. 확인된 최소 변경을 구현·검증하고 단계 상태와 인계는 프로젝트 권위에 기록한다. 무한 반복·고정 모델 분업·자동 병합을 시작하지 않는다.
