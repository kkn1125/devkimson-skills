# Codebase Guide

운영·유지보수 작업에 필요한 프로젝트 구조와 변경 영향 범위를 빠르게 파악하는 Codex 스킬입니다. 개발 경험은 있지만 해당 프로젝트가 낯선 개발자를 기준으로 하며, 언어와 프레임워크에 제한을 두지 않습니다.

전체 구조 요약, 기술 스택 확인, 실제 코드의 스타일 예시 추출, 기능 흐름 및 변경 영향 분석을 수행합니다. 결과는 Mermaid 다이어그램과 근거 링크를 포함한 Markdown으로 저장하고 이후 갱신합니다.

## Codex CLI에 설치

압축을 풀고 `SKILL.md`가 바로 들어 있는 `codebase-guide` 폴더를 다음 중 한 위치에 복사합니다.

| 범위 | 설치 위치 |
| --- | --- |
| 개인의 여러 프로젝트에서 사용 | `~/.agents/skills/codebase-guide/` |
| 특정 저장소에서 팀과 사용 | `<프로젝트 루트>/.agents/skills/codebase-guide/` |

Windows에서 `~`는 사용자 홈 폴더입니다. 예를 들어 개인 설치 경로는 `C:\Users\<사용자명>\.agents\skills\codebase-guide\`입니다. 폴더가 중첩되어 `codebase-guide/codebase-guide/SKILL.md`가 되지 않도록 확인합니다. 같은 이름의 스킬을 개인·저장소 위치에 중복 설치하지 않는 편이 명확합니다.

프로젝트 루트에서 Codex CLI를 시작하고 아래처럼 호출합니다. 설치한 스킬이 보이지 않으면 CLI를 다시 시작합니다.

```text
$codebase-guide 이 프로젝트의 구조와 주요 기술 스택을 요약해줘.
```

설치 위치와 탐색 동작은 [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)를 참고하세요.

## 사용법

프롬프트에는 **하려는 작업, 대상 기능·경로, 참조 가능한 자료, 원하는 분석 범위**를 적습니다. 알고 있는 정보만 제공하면 됩니다. 구체적인 작업이 있으면 전체 프로젝트 설명을 요청하기보다 그 작업부터 설명하는 편이 좋습니다.

기본 저장 위치는 `docs/codebase/`입니다. 기존 문서 관례나 사용자가 지정한 경로가 있으면 이를 우선합니다. 스킬은 분석 문서를 생성·갱신하며, 애플리케이션 수정·의존성 설치·DB 변경·배포는 별도 요청 없이는 수행하지 않습니다. 빌드·테스트·실행은 명령의 부작용과 허용 범위를 확인한 뒤 필요한 경우 수행합니다.

### 처음 보는 프로젝트 파악

```text
$codebase-guide 이 프로젝트를 처음 맡았어.
주요 기술 스택, 실행 단위, 핵심 모듈의 역할과 데이터 흐름을 빠르게 정리해줘.
실제 코드에서 개발 스타일 예시도 추출하고, 어디부터 읽으면 좋을지 알려줘.
다이어그램을 포함해 docs/codebase에 저장해줘.
```

### 기능 수정 전 영향 분석

```text
$codebase-guide 주문 취소 시 환불 처리 방식을 변경하려고 해.
현재 처리 흐름과 수정 시작 지점을 찾고, 연결된 API·DB·이벤트·배치의 영향을 추적해줘.
관련 코드 스타일 예시와 필요한 테스트를 정리해줘. 코드는 수정하지 마.
```

### 미사용 API 조사

```text
$codebase-guide /api/legacy 아래 API들의 삭제 가능성을 조사해줘.
프런트 소스는 ../frontend도 참조할 수 있어.
프런트 호출이 없다는 이유만으로 미사용을 확정하지 말고,
외부 연동·배치·인증 방식도 확인해줘.
API별로 사용 확인, 조사 범위에서 호출 미발견, 불명확을 구분해줘.
```

### 운영 장애 조사와 MCP 활용

```text
$codebase-guide 운영에서 결제 성공 후 주문 상태가 가끔 갱신되지 않아.
관련 실행 흐름과 트랜잭션·이벤트·재시도 처리를 분석해줘.
관찰된 사실과 원인 추정을 구분하고, 원인을 좁히기 위한 다음 확인을 제시해줘.
Dooray MCP로 내가 지정한 관련 티켓도 조회해줘.
```

MCP를 사용할 때는 실제 연결된 채널 이름과 티켓·문서·로그의 식별자 또는 조회 범위를 덧붙입니다. 연결되지 않았거나 접근할 수 없는 자료는 확인한 것으로 취급하지 않습니다. 인증정보나 토큰 원문을 프롬프트에 붙여 넣지 않습니다.

### 배치 재실행 영향 확인

```text
$codebase-guide 정산 배치가 중간에 실패해서 재실행하려고 해.
부분 저장, 중복 처리 방지, 외부 전송 여부와 재처리 범위를 확인해줘.
안전하게 재실행할 수 있는 조건과 불명확한 부분을 정리해줘.
배치 실행이나 데이터 변경은 하지 마.
```

### 기존 분석 갱신

```text
$codebase-guide docs/codebase의 기존 분석을 현재 소스 기준으로 갱신해줘.
이번에는 회원 인증 모듈 변경과 연결된 소비자를 집중 확인해줘.
다이어그램과 근거 링크도 갱신하고, 다시 확인하지 않은 영역은 구분해줘.
```

## 결과를 읽을 때

코드로 확인한 사실, 추론, 미확인 영역을 구분해 읽습니다. 의존성 선언은 실제 사용이나 운영 배포의 증거와 다릅니다. 프런트 호출 미발견이나 일정 기간의 트래픽 부재만으로 API가 미사용이라고 확정할 수 없습니다. 분석 결과는 조사한 저장소·환경·기준 시점 안에서 해석해야 합니다.
