# 스크린샷·목업 검토

## 입력의 범위

실제로 볼 수 있는 이미지인지 먼저 확인한다. 로컬 이미지라면 사용 가능한 이미지 보기 도구로 열고, 보지 않은 파일을 검토했다고 말하지 않는다.
캡처 번호, 전체 화면/크롭 여부, 읽을 수 있는 문구, 테마, 표시 상태를 기록한다.
이미지 해상도와 CSS 뷰포트는 다르다. 확대·축소·기기 픽셀 비율을 모르면 화면 픽셀을 CSS px로 환산하지 않는다.
작거나 흐린 글자는 확대해도 불명확하면 “문구 판독 불가”로 남긴다. OCR 결과도 원본과 대조한다.

## 확인할 수 있는 것

- 중요한 액션·제목·상태가 주변 정보와 구분되는가.
- 정렬선, 줄바꿈, 잘림, 겹침, 반복 액션, 가시 행 수, 화면 안의 밀도가 작업에 적절한가.
- 현재 위치와 선택 상태가 보이는가. 텍스트나 형태로 의미가 드러나는가.
- 표시된 데이터가 의미 있는 비교·선택을 돕는가. 시간·단위·출처가 필요한 위치에 있는가.
- 보이는 팝업·고정 요소가 읽기나 액션을 가리는가.

한 크기의 화면에서 관찰한 현상을 다른 크기까지 일반화하지 않는다.
정적 목업은 설계 상태로 평가하고 제품에 구현된 사실로 기록하지 않는다.

## 확인할 수 없는 것

단일 정지 이미지로 호버, 탭 순서, 접근 가능한 이름, 스크린리더 안내, 서버 권한, 삭제 확인·실행 취소, 저장 성공, 반응형 전환을 확정할 수 없다.
포커스 링이 안 보인다는 이유만으로 포커스 표시가 없다고 단정하지 않는다. 포커스를 받은 캡처인지 먼저 확인한다.
삭제 버튼이 보인다는 이유로 즉시 삭제된다고 말하지 않는다. 위험은 후속 동작 확인으로 연결한다.
캡처에서 회색 텍스트가 흐리면 가독성 후보로 적는다. 원본 색·배경·불투명도를 모르는 대비비는 추정값이다.

## 핵심 작업에 연결하기

“카드가 크다” 대신 “제공된 화면에는 항목 3개만 보여 목록을 비교하기 어렵다. 대량 처리 화면이라면 요약 정보와 패딩을 줄이는 편이 낫다”처럼 관찰과 조건을 분리한다.
“아이콘으로 바꾸기” 제안에는 의미를 알아볼 수 있는지, 이름·포커스·터치 동작을 제공할 수 있는지 확인 조건을 붙인다.
위치는 “캡처 2 · 오른쪽 상세 패널 · 하단 저장 버튼”처럼 다시 찾을 수 있게 적는다.

## 추가 자료 요청

현재 판단을 바꾸는 자료만 요청한다. 예: 긴 항목 캡처, 좁은 화면, 메뉴를 연 상태, 같은 화면의 밝은 테마, 삭제 후 흐름 설명.
자료가 없어도 확인 가능한 검토는 먼저 제공한다. 명확한 결론과 무관한 캡처·사용자 수를 일괄 요구하지 않는다.
확인을 위해 실제 운영 데이터 변경이나 삭제를 실행하지 않는다.
