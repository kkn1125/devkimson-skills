# 비판적 UX 진단

## 작업 흐름에서 마찰을 찾는다

기능이 있는지보다 사용자가 발견하고, 의미를 이해하고, 실행하고, 결과를 믿을 수 있는지 살핀다.
사용 목표·빈도·실수 비용을 모르면 가장 그럴듯한 가정을 밝히고 조건부로 평가한다.
페이지 설명만 있으면 흐름의 논리·용어·단계를 검토한다. 색·여백·위계가 실제로 어색하다고 단정하지 않는다.

| 흐름 | 질문 | 발견을 뒷받침할 근거 |
| --- | --- | --- |
| 발견 | 다음 행동이 어디 있는가? 현재 위치를 아는가? | 액션 위치·문구·현재 메뉴 상태 |
| 이해 | 무엇을 선택하며 결과가 무엇인지 아는가? | 이름·범위·단위·설명 |
| 선택 | 비교 정보와 선택 상태가 충분한가? | 중요한 열·차이·선택 수 |
| 실행 | 반복 입력·거리·불필요한 단계가 있는가? | 실제 단계·작업량·중복 액션 |
| 결과 | 완료·대기·실패를 구분할 수 있는가? | 완료 피드백·업데이트된 상태 |
| 복구 | 실수·실패 후 맥락을 유지할 수 있는가? | 입력 보존·재시도·실행 취소·복귀 |

## 정보 밀도와 위계

큰 카드가 대량 비교를 방해하는지, 작은 행이 식별과 조작을 방해하는지 작업 기준으로 판단한다.
제목·본문·시간·출처가 모두 같은 비중이면 비교에 필요한 핵심 정보를 먼저 구분한다.
패딩만 줄이기보다 중복 내용과 반복 액션을 먼저 정리한다. 숨기는 정보가 선택에 필요한지 확인한다.
입력 36~40px, 행 48~72px 같은 값은 데스크톱 시작점일 수 있지만 준수 기준은 아니다.
실제 폰트·내용 줄 수·입력 방식·기존 토큰을 기준으로 제안하고, 측정하지 않았으면 “조정 예시”라고 적는다.

## 액션과 발견성

주 액션의 강조는 사용 빈도와 중요도에 맞춘다. 모든 버튼을 강조하면 선택이 어려워진다.
반복 텍스트 버튼을 줄일 때 아이콘·호버·행 클릭의 비용을 비교한다. 중요한 액션을 호버에만 두지 않는다.
행 클릭과 내부 링크·체크박스·삭제 버튼의 동작이 충돌하는지 확인한다. 클릭 가능한 행 전체를 무조건 권하지 않는다.
파괴적 액션은 대상·범위·결과·복구 가능성을 분명히 한다. 매번 확인 모달을 넣는 대신 실제 손실 위험에 맞는 예방·확인·실행 취소를 선택한다.

## 상태와 내용

빈 상태는 “데이터 없음”, “필터 결과 없음”, “권한 없음”, “아직 로딩 중”을 필요한 만큼 구분한다.
오류는 사용자가 고칠 수 있는 대상과 재시도를 알려주고 입력·선택·검색 맥락을 가능한 한 유지한다.
상태 의미는 색만으로 전달하지 않는다. 상태마다 다른 색을 추가해야 하는 것은 아니다. 텍스트가 충분하면 절제된 색도 가능하다.
한국어 용어·말투·영문 혼용은 의미와 제품 규칙에 맞춘다. “알림/알림함”의 차이가 혼란을 만드는지 확인하고 이름 차이만으로 결함을 만들지 않는다.
데모 데이터처럼 보이는 값은 의심으로 기록한다. 캡처가 운영 화면이라는 근거 없이 유출·운영 오류로 단정하지 않는다.
긴 값은 잘림 여부와 함께 전체 값 접근·복사·비교 가능성을 본다. 중요한 정보를 툴팁에만 옮기지 않는다.

## 내비게이션과 구조

메뉴 개수보다 사용자가 범주를 이해하고 원하는 곳을 찾을 수 있는지 본다.
메뉴 IA 정리나 종합 검토는 [구조와 컴포넌트](structure-and-components.md)에서 사이드바/아이콘의 중복·보완, 알림/메일의 팝오버 대안, 빈도 기반 그룹·순서를 대조한다.
7개를 넘는다는 이유만으로 그룹을 강제하지 않는다. 빈도·업무 개념·깊이 증가의 비용을 비교한다.
팝업·상세 패널·고정 버튼은 현재 작업을 가리거나 문맥을 끊는 실제 상황에서 지적한다.
여러 단계의 폼은 오류 복구와 재방문이 가능해야 한다. 단계 수를 줄이면 복잡한 선택이 한 화면에 몰리는지 확인한다.

## 제안의 반대 비용

각 제안은 기존 디자인 시스템 안에서 가장 작은 변경부터 검토한다.
밀도 개선 → 클릭 영역·읽기 유지, 정보 숨김 → 발견성·키보드·터치 유지, 강조 추가 → 다른 주 액션과 경쟁 확인.
대안이 모두 타당하면 제품 조건과 선택 기준을 제시한다. 취향 하나를 유일한 정답처럼 말하지 않는다.
효과가 작고 수정 비용·회귀 위험이 큰 재설계는 기본안으로 제안하지 않는다.
