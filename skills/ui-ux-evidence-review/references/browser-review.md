# 실제 브라우저 검토

## 조건과 조작 범위

제공된 URL·실행 중인 앱을 사용 가능한 브라우저 도구로 연다. 별도 개발 서버·패키지 설치가 필요한 경우 프로젝트 실행 절차와 요청 범위를 확인한다. URL만 받았을 때 임의의 저장소를 같은 구현이라고 가정하지 않는다.
접속할 수 없으면 확보된 자료로 계속하고 실행 확인을 미확인으로 남긴다. 사용자 인증정보를 요구하거나 실패한 로그인·접속을 반복하지 않는다.

버전·경로, 역할, 데이터 상태, 테마, CSS 뷰포트, 확대율을 판단에 필요한 만큼 기록한다. 창 크기·이미지 해상도를 뷰포트로 대신하지 않는다.
메뉴 열기·닫기, 포커스 이동, 스크롤, 화면 크기 변경은 업무 데이터에 영향이 없을 때 확인할 수 있다.
검색·필터·상세 진입도 자동 저장·읽음 처리·외부 전송 등의 부작용이 있는지 확인한다. 무해한 조작에 재승인을 요구하지 않는다.
저장·삭제·승인·발송을 재현해야 하면 사용자가 허용한 환경·데이터·동작 범위인지 먼저 확인한다. 범위가 불명확하면 해당 동작 전에서 멈추고 관찰·코드 근거로 검토한다. 테스트 환경이라는 이름만으로 무제한 변경 권한을 가정하지 않는다.

## 요청에 맞는 확인 범위

단일 문제는 해당 상태와 회귀 가능성이 있는 가까운 경로를 확인한다. 종합 검토는 제품이 지원하는 화면·입력 방식에서 아래 항목을 확인하고 실행 여부를 남긴다.

| 조건 | 살필 내용 |
| --- | --- |
| 데스크톱·좁은 폭·가로 화면 | 주 액션 접근, 줄바꿈·겹침·스크롤, 고정 요소와 메뉴 배치 |
| 긴 문구·긴 식별자·많은 항목 | 잘림, 전체 값 접근, 비교 정보, 검색·선택 범위 |
| 키보드 | Tab/Shift+Tab 순서, 보이는 포커스, 해당 패턴의 실행·닫기·포커스 복귀 |
| 확대·큰 텍스트 | 내용·기능 손실과 고정 높이·팝업 잘림; 수치 판단은 접근성 문서 사용 |
| 메뉴·팝업·모달 | 초기/복귀 포커스, Escape, 패턴에 맞는 포커스 범위, 바깥 클릭, Tab 순서, Enter, 중첩 상태, 화면 가장자리·스크롤 |
| 모션·테마 | 적용되는 reduced-motion 동작과 같은 요소의 테마·상태별 회귀 |
| 로딩·빈 결과·오류 | 제공된 fixture나 허용된 재현에서 피드백·입력 보존·복구 |

폭은 제품의 지원 범위와 실제 깨지는 경계를 기준으로 정한다. 예시 기기 크기를 통과 기준으로 고정하지 않는다. 레이아웃 문제는 높이도 확인한다.
긴 문구 등은 제공된 자료나 허용된 로컬 fixture로 확인한다. 운영 데이터를 검토용으로 바꾸지 않는다. 개발자 도구로 만든 상태는 실제 제품 상태와 구분한다.
뷰포트 축소는 레이아웃 확인이며 실제 모바일 기기·터치·가상 키보드 검증이 아니다. DOM 포커스 확인도 스크린리더 조작을 대신하지 않는다.
접근성 수치·예외를 판단하려면 [접근성](accessibility.md)을 읽는다.
모달/팝업/드롭다운 동작은 [인터랙션 검토](interaction-review.md)에 따라 대상 목록과 실제 키 입력 결과를 남긴다. 포커스 문제 모달 전체 목록과 미확인 대상은 구분한다.

## 재현과 종료

발견에는 찾을 수 있는 위치, 재현 조건·단계, 실제 결과, 핵심 작업 영향을 남긴다. 필요한 화면 캡처를 근거로 보관하되 계정·개인정보를 불필요하게 복제하지 않는다.
네트워크·콘솔 오류만으로 UI 실패를 선언하지 않는다. 사용자에게 보이는 현상과 관련 구현·응답을 연결한다.
화면의 완료 표시가 서버 저장 성공을 증명하지 않는다. 저장 확인은 실제 요청·응답·조회 근거가 제공된 범위에서만 말한다.
수정 후에는 같은 조건에서 재현이 사라졌는지와 연결된 상태의 회귀를 확인한다. 버전·데이터·폭이 달라지면 비교 한계를 적는다.
확인한 문제와 결과를 바꿀 미확인 항목이 정리되면 끝낸다. 전체 매트릭스나 새 기능을 임의로 추가하지 않는다.
