# 접근성: 기준·예외·확인 범위

WCAG 2.2의 A/AA 관련 항목을 일반 검토의 기준으로 사용한다. 제품이 지정한 목표가 있으면 그 목표를 적용한다.
이 문서는 주요 UI 문제를 살피는 가이드이며 WCAG 전체 체크리스트나 인증 절차가 아니다.
규범은 [WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/), Understanding과 APG는 해설·구현 지침이다.
아래 수치가 모든 요소·상황에 동일하게 적용되는 것은 아니다. 기준 번호와 적용 조건을 함께 기록한다.

## 시각 기준

| 항목 | 적용 기준 | 검토 시 주의 |
| --- | --- | --- |
| 일반 텍스트 | 1.4.3 AA: 4.5:1 이상 | 비활성·장식·로고 등 예외 확인 |
| 큰 텍스트 | 1.4.3 AA: 3:1 이상 | 18pt 이상 또는 14pt 이상 굵은 글씨; CSS 환산 약 24px / 18.67px |
| 필수 UI 식별·상태·그래픽 | 1.4.11 AA: 인접 색과 3:1 이상 | 모든 경계선·장식에 적용하지 않음; 비활성·수정하지 않은 UA 표현 등 예외 |
| 색에만 의존한 의미 | 1.4.1 A | 텍스트·형태·패턴 등 다른 수단 확인 |
| 포인터 타깃 | 2.5.8 AA: 24×24 CSS px 이상 또는 기준의 예외 | 간격·동등한 대안·인라인·UA 제어·필수 표현 예외 확인 |

본문 대비는 [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), UI 대비는 [Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)를 확인한다.
24×24는 눈에 보이는 아이콘 크기가 아니라 실제 타깃 크기다. 작은 타깃의 간격 예외는 각 중심의 지름 24 CSS px 원이 다른 타깃·다른 작은 타깃의 원과 겹치는지 확인한다. 단순히 아이콘 간 24px 간격이라고 바꾸지 않는다. [Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
44×44 CSS px은 2.5.5 AAA의 기준이며 예외가 있다. 32~40px 같은 디자인 권장값이나 AAA 값을 AA 의무로 오인하지 않는다.

### 측정

원본 스타일 또는 computed style의 실제 전경·배경을 기록한다. 반투명·그라데이션·이미지 배경은 실제 합성·위치를 확인한다.
안티앨리어싱된 글자 가장자리 픽셀만 샘플링해 대비 위반을 확정하지 않는다. 이미지 색 샘플만 있다면 추정임을 적는다.
불투명 sRGB 색상 쌍은 [contrast.py](../scripts/contrast.py)로 계산할 수 있다. 입력·조건·임계값을 함께 보고한다.
비교는 반올림 전 값으로 한다. 수치 통과도 실제 가독성·전체 화면 준수를 보장하지 않는다.

## 키보드·의미·피드백

- 2.1.1 A·2.1.2 A: 핵심 기능을 키보드로 수행하고 포커스가 갇히지 않는지 확인한다.
- 2.4.3 A·2.4.7 AA: 의미 있는 포커스 순서와 보이는 표시를 확인한다.
- 2.4.11 AA: 작성자 콘텐츠가 포커스 받은 요소를 완전히 가리지 않는지 확인한다. 완전 비가림은 2.4.12 AAA이다.
- 2.4.13의 포커스 표시 면적·대비 요구는 AAA이다. 해당 기준을 AA 필수로 말하지 않는다. [Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)
- 4.1.2 A·2.5.3 A: 이름·역할·상태가 제공되며 보이는 이름이 접근 가능한 이름에 포함되는지 확인한다.
- 폼에는 연결된 이름·지시·오류 식별과 필요한 오류 수정 안내를 확인한다(3.3.1 A·3.3.2 A·3.3.3 AA).
- 비동기 결과·오류·진행 상태를 포커스 이동 없이 알려야 하는 경우 4.1.3 AA를 확인한다. 모든 변화를 live region으로 읽게 만들지 않는다. [Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

툴팁이 있다는 이유만으로 아이콘 버튼의 접근 가능한 이름이 있다고 단정하지 않는다.
호버·포커스 추가 콘텐츠는 적용되는 경우 닫기·포인터 이동·유지가 가능해야 한다. [Content on Hover or Focus, 1.4.13 AA](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)
모달의 초기 포커스·Tab 범위·닫기·복귀는 사용하는 패턴과 실제 동작을 확인한다. [APG Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 확대·반응형·모션

1.4.4 AA는 텍스트 200% 확대에서 내용·기능 손실을 살핀다(캡션·이미지 텍스트 등 적용 예외 있음).
1.4.10 AA는 세로 스크롤 콘텐츠의 320 CSS px 폭에서 불필요한 양방향 스크롤과 손실을 살핀다. 400% 줌은 시작 폭과 기기 조건을 기록한다.
본질적으로 2차원 배치가 필요한 표·지도 등에는 예외가 있지만 주변 UI와 개별 셀 내용까지 무조건 면제되지 않는다. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
텍스트 간격 변경에서 잘림·기능 손실이 있는지도 확인한다(1.4.12 AA). 한 화면 캡처로 확대와 간격 변경 동작을 추정하지 않는다.
모션은 자동 이동·깜박임·상호작용 애니메이션을 구분한다. reduced-motion 확인은 유용하지만 CSS 미디어쿼리 존재만으로 접근성 준수를 선언하지 않는다. 2.3.3은 AAA이며 관련 A/AA 요건과 혼동하지 않는다.

## 실행 검증의 범위

가능한 환경에서 문제 후보에 맞춰 Tab/Shift+Tab, Enter/Space, Escape, 확대, 좁은 폭, 스크린리더 이름·상태를 확인한다. 컴포넌트별 키 동작이 다르면 적용 패턴을 따른다.
캡처는 시각 증거, DOM·코드는 구현 증거, 실제 키보드·보조기기 조작은 동작 증거다. 서로 대신하지 않는다.
실제로 실행한 브라우저·입력 방식·상태만 기록한다. 미실행 검사를 “통과”로 채우지 않는다.
문제가 없을 때도 “확인한 항목에서 문제 미발견”이라고 표현한다. 전체 접근성 인증을 선언하지 않는다.
