# Excalidraw 다이어그램

관계와 흐름을 그림의 배치로 표현합니다. 기존 그림을 수정할 때는 요청 범위의 변경을 우선합니다.

## 실행 방식 선택

- **Office의 Excalidraw 함께 그리기 또는 캔버스 도구가 있는 환경**: 먼저 [Office 캔버스 지침](references/office-canvas.md)을 읽습니다. 현재 장면과 선택 도형·코멘트를 바탕으로 변경안을 만듭니다. 파일 생성 지침을 캔버스 도구에 그대로 적용하지 않습니다.
- **독립 파일을 요청한 경우**: [JSON 구조](references/json-schema.md)와 [도형 템플릿](references/element-templates.md)을 읽고 `.excalidraw` 파일을 생성합니다. 아래 파일 작성·렌더링 절차를 따릅니다.
- 설명만 요청했다면 그림을 임의로 수정하지 않습니다. 사용 가능한 도구와 응답 스키마가 이 문서의 예시와 다르면 현재 도구 계약을 따릅니다.

## 그리기 전 판단

1. 독자와 전달할 내용을 정하고, 개요인지 구현 설명인지 구분합니다. 간단한 개요에 불필요한 상세를 덧붙이지 않습니다.
2. 실제 시스템을 다룰 때는 제공 자료, 소스, 공식 문서에서 구성 요소와 연결 방향을 확인합니다. API·이벤트·데이터 이름을 추측해서 사실처럼 넣지 않습니다. 미확인 관계는 가정임을 표시합니다.
3. 분기·합류·순서·계층·순환·비교 중 핵심 관계를 정합니다. 시선이 움직일 방향과 구역 간 연결을 먼저 배치합니다.
4. 기존 그림이 있으면 해당 구역의 위치, 간격, 색상과 표현 방식을 따릅니다. 전체 재배치가 필요하지 않다면 유지합니다.

## 관계에 맞는 배치

| 관계 | 배치 |
| --- | --- |
| 하나에서 여러 개로 분기 | 출발점에서 대상들로 퍼지는 화살표 |
| 여러 입력을 집계 | 입력들이 한 처리 지점으로 모이는 구조 |
| 단계별 진행 | 좌→우 또는 위→아래의 일관된 순서 |
| 상위·하위 관계 | 트리와 연결선, 깊이에 따른 들여쓰기 |
| 피드백·재시도 | 결과에서 이전 단계로 돌아가는 경로 |
| 변환 | 입력과 출력의 차이를 처리 단계 양쪽에 배치 |
| 전후·대안 비교 | 같은 기준으로 정렬한 병렬 구조 |
| 책임·단계 구분 | 제목과 여백으로 구역을 나누고 경계를 넘는 연결 표시 |

모든 항목을 같은 카드에 넣지 않습니다. 처리 주체, 판단, 연결 대상에는 도형을 쓰고 제목·주석에는 독립 텍스트를 우선합니다. 단순한 순서도에는 일관된 도형을 유지해도 됩니다.

큰 그림은 전체 흐름, 책임별 구역, 필요한 상세 순으로 읽히게 만듭니다. 기술 설명에 도움이 될 때만 실제 요청·응답 예시나 이벤트명을 넣습니다. 비밀값과 개인정보는 예시에서 제거합니다.

## 색상·글자·간격

- 새 그림은 [의미별 팔레트](references/color-palette.md)를 참고합니다. 사용자 지정 스타일과 기존 캔버스의 일관성을 우선합니다.
- 같은 의미는 같은 색으로 표시하고 색만으로 상태를 구분하지 않습니다. 짧은 라벨이나 도형을 함께 사용합니다.
- 텍스트와 배경의 대비를 확인합니다. 어두운 채움에 어두운 기본 글자가 놓이면 밝은 채움을 선택합니다.
- 한국어는 한국어를 지원하는 글꼴을 사용합니다. 파일 모드에서는 `fontFamily: 2`를 출발점으로 삼고, 캔버스 모드에서는 앱이 정하는 글꼴을 유지합니다.
- 파일 모드의 일반 글자는 16–20px, 제목은 24–32px 정도에서 시작합니다. 내용에 맞춰 도형을 넓히거나 라벨을 줄입니다.
- 기본 도형은 180×90px 정도, 요소 간 여백은 60–100px 정도에서 시작합니다. 글자 크기를 줄여 억지로 맞추지 않습니다.
- 전문적인 도식의 기본값은 `roughness: 0`, `opacity: 100`입니다. 사용자가 손그림 스타일을 요청하면 조정합니다.
- 화살표가 글자나 다른 도형을 관통하지 않도록 배치합니다. 캔버스가 경유점을 지원하지 않으면 도형 위치와 간격으로 해결합니다.

## 독립 파일 작성

이 절은 `.excalidraw` 파일을 만들거나 수정할 때만 적용합니다.

```json
{
  "type": "excalidraw",
  "version": 2,
  "source": "https://excalidraw.com",
  "elements": [],
  "appState": { "viewBackgroundColor": "#ffffff" },
  "files": {}
}
```

- 위 구조에 실제 도형을 채웁니다. 빈 `elements`는 결과물이 아닙니다.
- [도형 템플릿](references/element-templates.md)의 색상 자리표시자를 실제 팔레트 색상으로 바꾸고 ID를 각각 고유하게 부여합니다.
- 텍스트의 `text`와 `originalText`를 함께 갱신합니다. 도형에 결합된 텍스트는 `containerId`와 부모의 `boundElements`가 일치해야 합니다.
- 화살표의 `points`는 요소 좌표에 대한 상대값입니다. 바인딩과 연결 대상의 역참조를 함께 확인합니다. 잘못된 ID나 삭제된 대상을 연결하지 않습니다.
- 기존 파일을 편집할 때는 관계없는 요소, 이미지의 `files`, 그룹과 바인딩 정보를 보존합니다. 참고 스키마는 요약이므로 기존 요소의 다른 필드를 일괄 삭제하지 않습니다.
- 큰 그림은 구역별로 작성한 뒤 구역 간 연결과 전체 간격을 확인합니다. 필요하면 생성 코드를 사용하되 최종 JSON을 검증합니다.

### PNG 렌더링

보조 렌더러는 [render_excalidraw.py](references/render_excalidraw.py), 브라우저 템플릿은 [render_template.html](references/render_template.html)입니다. 의존성은 [pyproject.toml](references/pyproject.toml)에 있습니다.

Python 3.11 이상과 `uv`를 사용하는 환경에서, 설치된 스킬의 `references` 디렉터리로 이동한 뒤 실행합니다. 원본 스크립트 도움말의 `.claude/skills/...`는 예시 경로이며 실제 설치 경로를 사용합니다.

```bash
uv sync
uv run playwright install chromium
uv run python render_excalidraw.py "/absolute/path/diagram.excalidraw"
```

PNG는 기본적으로 입력 파일 옆에 생성됩니다. 렌더러는 Chromium에서 esm.sh의 Excalidraw 모듈과 폰트를 불러오므로 네트워크가 필요합니다. 설치·네트워크 사용이 제한되면 기존 Excalidraw 앱의 미리보기나 내보내기를 사용합니다. 이 렌더러는 회전 요소나 복잡한 경로의 화면 경계를 완전히 보장하지 않으므로 결과 이미지를 확인합니다.

## 확인 및 수정

JSON이나 도구 호출 성공만으로 시각 검토가 끝났다고 판단하지 않습니다. 가능한 환경에서 렌더링한 PNG 또는 실제 캔버스를 보고 다음을 확인합니다.

- 처음 정한 흐름과 분기·합류·순환 방향이 그림에 드러나는지
- 글자 잘림, 의도하지 않은 겹침, 지나치게 작은 글자가 없는지
- 화살표가 올바른 대상에 닿고 경로와 라벨이 구분되는지
- 같은 단계의 간격과 정렬이 맞고 특정 구역만 과밀하지 않은지
- 요청하지 않은 기존 도형·코멘트·이미지가 보존됐는지

문제가 보이면 해당 구역을 수정하고 다시 확인합니다. 실제 이미지나 캔버스를 볼 수 없다면 수행한 구조 검증과 시각 검토 미실시를 구분해서 전달합니다. 적용 전 제안만 만든 경우에는 완료 대신 제안 상태로 알립니다.
